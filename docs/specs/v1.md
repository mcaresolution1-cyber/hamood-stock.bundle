Build version 1 of "Hamood Stock" in this repo. Read CLAUDE.md first and follow its rules strictly, especially the stock ledger rules. The project setup (schema, auth, i18n, seed, app shell) is already done. No barcode features.

## Goal
A simple web app where staff record stock coming IN to each warehouse and track every unit going OUT, with full history. It must be fast on a phone: a stock entry should take under a minute.

## Build in this order. After each phase run lint, typecheck, tests and build, and make a commit.

### Phase 1: Master data (ADMIN only)
- Products: list with search (by model code or name, EN/AR) and a category filter; create and edit; deactivate instead of delete. Import products from an Excel or CSV file with columns modelCode, nameEn, nameAr, category, variant, imageUrl, cost, lowStockLevel. Show a preview, report errors per row and update existing model codes.
- Warehouses: list, create, edit, deactivate; kind SELLABLE or DAMAGED.
- Users: list, create, edit, deactivate, reset password; set role (ADMIN, STAFF, VIEWER) and assigned warehouses.
- Opening stock: ADMIN uploads an Excel file (modelCode, quantity) for one warehouse; this saves one IN entry with reason OPENING_STOCK through the normal entry service.

### Phase 2: Stock entry core
- One server-side service, e.g. src/server/stock/createEntry.ts, that every entry goes through. It follows the transaction rules in CLAUDE.md. Write Vitest tests for: numbering, an IN increasing stock, an OUT decreasing stock, an OUT blocked when stock is not enough (nothing saved), a transfer creating both linked entries, a void reversing exactly, and two concurrent OUTs on the last unit (only one succeeds).
- Stock In form. Pick the warehouse (pre-selected if the user has only one) and a reason: Supplier delivery (supplier name + invoice no. required), Customer return (order no. or customer name required, plus "resellable / damaged"; damaged goes to the DAMAGED warehouse), or Correction + (ADMIN only, note required). Add lines with a product picker: a searchable command box showing model code, name and photo, then quantity. Optional photo upload of the delivery note. Show a summary screen before saving. After saving, show the entry number and offer "New entry" or "Repeat last entry".
- Stock Out form. Reasons: Website order (WooCommerce order no.), Direct sale (customer name + phone), Installation (technician + customer), Transfer (destination warehouse), Return to supplier (ADMIN), Damaged/lost (ADMIN, note required), Correction − (ADMIN). Show the available quantity beside each product as it is picked. Block quantities above what is available, with a clear message such as "Only 3 HMD-772 left in Riyadh Main".
- Entry list and detail: number, date, type, reason, warehouse, reference, user, lines. Filter by date range, warehouse, type, reason, user and product. ADMIN sees a "Void" button with a confirm dialog and a required reason.
- Printable delivery note page (A4, Arabic + English) for any OUT entry.

### Phase 3: Stock views and reports
- Home dashboard: two large buttons (Stock In, Stock Out), a product stock search, and cards for total products, low-stock count and today's entries.
- Product page: stock per warehouse and that product's movement history (a running "stock card").
- Reports, all with Excel export:
  1. Stock on hand: quantity per product per warehouse, totals, category filter. Stock value shows for ADMIN only.
  2. Movement history: every line with filters.
  3. Low stock: products at or below lowStockLevel per warehouse.
  4. Stock out by reason: units per reason per month, filterable by warehouse.

### Phase 4: Polish
- Every screen works well at 375px wide and on desktop. Large touch targets on the entry forms.
- Complete Arabic translations and a correct RTL layout on every page.
- Loading and empty states, friendly error messages, and toasts on save.
- Audit: each entry shows who created it and when; voids show who voided it and why.
- Update CLAUDE.md and the README with how to run, deploy (Vercel + a managed Postgres such as Neon) and add users.

## Rules
- Enforce role and warehouse permissions on the server for every action. STAFF must never see cost or stock value.
- Never write to StockLevel outside the entry service. Never hard-delete entries, products, users or warehouses.
- Keep components small and typed. Validate every form with Zod on both client and server.
- If something in this spec is unclear, choose the simplest reasonable option, note it in the PR description and keep going.

When all phases are done, open one pull request with a summary per phase, screenshots of the main screens (mobile and desktop, EN and AR) if you can take them, test results, and a list of the decisions you made that I should review.
