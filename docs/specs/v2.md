# Hamood Stock — Improvement Brief (prompt for the developer / AI coding agent)

You are working on **Hamood Stock**, the internal multi-warehouse inventory app for **Hamood TV (حمود للطاولات)**, a Riyadh retailer of TV wall mounts, floor stands, monitor mounts and TV tables that sells through **hamoodtv.com (WooCommerce)**, in-shop/phone sales, and installation jobs done by technicians.

**Fixed constraints — do not change:**
- Stack: Next.js (App Router) + Prisma. Everything (app + database) stays on **Hostinger Business hosting**; no external services. GitHub → Hostinger deploy stays as is.
- Bilingual **English / Arabic** with full RTL. Every new string, email, PDF, error and Excel header must exist in both languages.
- Barcode scanning is still out of scope, but the data model must be ready for it.
- Timezone for all dates, reports and day boundaries: **Asia/Riyadh**. Currency: **SAR**.
- Keep the current clean, minimal visual style and the existing "What happened?" reason-card flow — it is good. Extend, don't redesign.

**Current state (reviewed live):** Dashboard, Stock in (Supplier delivery / Customer return / Correction +), Stock out (Website order / Direct sale / Installation / Transfer / Return to supplier / Damaged-lost / Correction −), Entries (filterable ledger with Void), Reports (Stock on hand, Movement history, Low stock, Stock out by reason — Excel export), Products (with Import), Opening stock (CSV: modelCode, quantity), Warehouses (Sellable / Damaged types), Users (Admin / Staff / Viewer, per-warehouse access).

Work through the changes below **in priority order**. For each item, implement it, add/adjust Prisma migrations, translate all strings, and meet the acceptance criteria.

## P0 — Bugs and integrity (fix first)

1. **Language switch crashes the page.** On `/admin/users`, clicking "عربي" produced the global "Something went wrong" page; console shows `TypeError: Failed to fetch` from the server action. The language did not change after "Try again".
   - Make the locale switch a simple cookie set + `router.refresh()` (or a plain link to a route handler that sets the cookie and redirects back). It must work on every page, including admin pages and pages with open modals.
   - Add retry/timeout handling for server actions on Hostinger (slow cold starts). Never show the full-page error for a transient network failure — show a toast "Connection problem, try again" and keep the user's form data.
   - The error page itself is English-only — translate it and include a "Report problem" detail (error id + timestamp) that is logged server-side.
2. **Stock must be calculated inside a database transaction with row locking.** Two staff submitting stock-out for the same product at the same moment must never drive stock negative. Re-check availability server-side at submit (not only in the product picker), use `SELECT … FOR UPDATE` / Prisma interactive transactions on a per-product-per-warehouse balance row, and return a clear per-line error ("Only 3 left in Riyadh Main").
3. **Double-submit protection.** Disable "Review/Confirm" after the first click and send an idempotency key per form so a slow connection can't create the entry twice.
4. **Ledger is immutable.** Entries can never be edited or deleted — only voided by a reversing entry. Void must: be Admin-only (or Manager, see roles), require a reason, link to the original entry, show both in Entries, and be blocked if it would make stock negative.
5. **Header/navigation layout.** At normal laptop width the brand truncates ("Hamood Sto…") and menu items wrap onto two lines ("Stock / in", "Opening / stock"). Group admin items under one **"Admin"** dropdown (Products, Opening stock, Warehouses, Users, Suppliers, Settings), keep Dashboard / Stock in / Stock out / Entries / Reports as top-level, and use a hamburger drawer below `md`. Verify in both LTR and RTL.

## P1 — Core business features (needed before real daily use)

### 1. Product master — make it commercially complete
Add to the product model and form:
- **SKU** (unique, internal) separate from **Model code** (as printed on the box). Keep model code searchable.
- **WooCommerce product ID / SKU** mapping field (needed for website sync later).
- **Barcode** (optional, unique if set) — for future scanning.
- **Selling price (SAR, incl. VAT)** and **Cost (SAR)**. Cost stays Admin/Accountant-only. Store cost history; compute **weighted-average cost** from supplier deliveries.
- **Default supplier** (link to Supplier master, below).
- Structured variant attributes instead of a free-text "Variant": `size range` (e.g. 32–70"), `colour`, `max load (kg)`, `VESA` — optional fields, shown on product cards and searchable.
- **Image upload** to Hostinger storage (resize to thumbnail) instead of only an "Image URL".
- **Reorder level + reorder quantity per warehouse** (keep the global low-stock level as the default). Also `lead time (days)`.
- Product status: Active / Discontinued (sell remaining, don't reorder) / Inactive.
- Products list must show: thumbnail, model code, name (current language), category, **on-hand per warehouse**, total sellable, total damaged, and (for Admin) stock value. Export to Excel.
- Import: show a **preview with row-level validation** (duplicate codes, unknown category, bad numbers) before saving; allow downloading the error rows.

### 2. Supplier master (new)
- Suppliers page under Admin: name (EN/AR), contact person, phone, email, city/country, VAT number, payment terms, notes, active flag.
- "Supplier" in Supplier delivery and Return to supplier becomes a **searchable dropdown** (with "Add new supplier" inline), not free text.
- Warn if the same **invoice no. + supplier** has already been received (duplicate invoice check).

### 3. Stock in improvements
- **Supplier delivery:** capture **unit cost per line** (Admin/Manager only; Staff can leave blank and a manager fills it later — mark entry "Cost pending"). Optional PO/reference no. Delivery-note photo stays; allow multiple photos.
- **Customer return:** require the **original order no. or link to the original stock-out entry**; a return reason (Wrong size, Customer changed mind, Defective, Damaged in delivery, Installation cancelled, Other); block returning more units than were sold on that order. Resellable → sellable warehouse; Damaged → damaged warehouse (already exists — keep).
- **Correction +:** require a reason and route through approval (see Controls).

### 4. Stock out improvements
- **Website order:** order no. required and **unique** across non-voided entries (warn on duplicate). Validate format of hamoodtv.com order numbers.
- **Direct sale:** Saudi phone validation (`05XXXXXXXX` / `+9665XXXXXXXX`), optional invoice/receipt no., payment method (Cash / Card / Transfer) for reconciliation, salesperson.
- **Installation:** this is the highest-leakage flow — make it a proper job:
  - Fields: technician (user with Technician role), installation date, customer name, phone, district/address, job/order no.
  - Two steps: **Issue to technician** (stock leaves warehouse into technician custody) → **Close job** (mark units *installed*, *returned unused* (back to stock), or *damaged*). Show an "Open installation jobs" list with age in days.
  - Report: units in technician custody, jobs open > 2 days.
- **Transfer:** make it **two-step: Dispatch → Receive**. Dispatch moves stock to an "In transit" state; the receiving warehouse confirms quantities; any difference creates a discrepancy that needs a manager decision. Show "Transfers in transit" on the dashboard. Transfers into a Damaged warehouse should be labelled "Move to damaged" with a required reason.
- **Return to supplier:** supplier dropdown, RMA/reference no., reason, expected credit (SAR), status (Sent / Credit received).
- **Damaged / lost:** require reason category (Broken in warehouse, Broken in delivery, Missing, Expired/obsolete), **photo required for "Broken"**, and approval above a threshold. Clarify the difference in UI: *Move to damaged warehouse* (still owned, may be repaired/returned to supplier) vs *Write off* (gone).
- **Correction −:** reason required + approval (see Controls). Prefer that corrections come from a Stock count (below).
- Product picker: show **available quantity in the selected warehouse** next to each product, and the line quantity input must not exceed it.

### 5. Reserved vs available stock
- Add a **Reservation** concept: a website order or phone order that is confirmed but not yet dispatched can reserve stock. Show **On hand / Reserved / Available** everywhere stock is shown. Reservation is released on dispatch (becomes stock-out) or cancel. This prevents selling the same last unit twice across shop, phone and website.

### 6. Stock count / cycle count module (new)
- Create a count for a warehouse (full or by category). Staff see a **blind count sheet** (no system quantity shown), enter counted quantities on mobile, submit.
- Manager reviews a **variance report** (system vs counted, units and SAR value), approves, and the system posts Correction +/− entries automatically, linked to the count.
- Lock outgoing movements for products under count, or snapshot quantities at count start.
- Report: shrinkage by month/warehouse/category.

### 7. Controls, approvals and roles
- Roles: **Admin**, **Warehouse Manager** (approve corrections, write-offs, transfer discrepancies, voids for their warehouses), **Staff**, **Technician** (mobile-only: see his issued items, close jobs), **Accountant** (read-only, sees cost and valuation), **Viewer**.
- Approval rules (configurable in Settings): Corrections, Damaged/lost and Voids above X units or Y SAR need Manager/Admin approval. Pending items show on the dashboard; entry does not affect stock until approved.
- Full **audit log**: who changed product prices/costs, user roles, warehouse settings, approvals — with before/after values.
- Security: password minimum length, forced change on first login, session timeout, rate-limited login, login history per user, optional email-based password reset (Hostinger SMTP).
- Users list: show last login; prevent deactivating the last Admin.

### 8. Documents and numbering
- Sequential, human-readable numbers per type: `IN-2026-00001`, `OUT-…`, `TRF-…`, `ADJ-…`, `CNT-…`.
- Printable **bilingual PDF / print view** for each entry: Delivery note (stock out), Goods received note (stock in), Transfer note, Gate pass — with company logo, entry no., date (Riyadh), items, quantities, recorded by, and signature lines (Issued by / Received by).
- After submitting: success screen with the entry number, "Print", "View entry", and "Record another".

## P1 — Reports (add to the existing four)

All reports: date range, warehouse, category, product filters; filters kept in the URL; Excel **and** PDF export; Arabic/English headers; Riyadh time.
1. **Stock valuation** — qty × weighted-average cost per product/warehouse/category, as of any date.
2. **Product stock ledger (stock card)** — every movement of one product with running balance per warehouse.
3. **Sales velocity & days of cover** — average daily out (sales reasons only), days of stock left, **reorder suggestion** = (avg daily sales × (lead time + safety days)) − available − on order.
4. **Slow-moving / dead stock & aging** — days since last sale, buckets 0–30 / 31–90 / 91–180 / 180+, with value.
5. **Shrinkage & adjustments** — corrections, damaged/lost, count variances by month, warehouse, user, in units and SAR.
6. **Supplier deliveries** — received by supplier and period, value, return-to-supplier and credit status.
7. **Installation report** — units per technician, open jobs, returned-unused rate, damaged on installation.
8. **Transfers report** — in transit, completed, discrepancies.
9. **Channel mix** — units out by Website / Direct sale / Installation per month (business insight on channel performance).
10. **User activity** — entries per user per day, voids and corrections per user.
- Optional: weekly email of Low stock + Pending approvals to admins (Hostinger cron + SMTP).
