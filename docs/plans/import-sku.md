# Automatic HMD SKUs and a smart import for the old POS export

## Summary
Owner's request (2026-10-19):
- Every product gets a **unique SKU generated by the app**, starting with `HMD00` and numbered in order.
- The details that matter: **SKU, name, category, price, stock available, images**; everything else optional.
- The import must be smart enough to take the old software's product export and sort it into these fields.

The old export (Ultimate-POS style, 431 rows) has: one row per product **per warehouse** ("Business
Location"), prices as `﷼ 500.00`, stock as `1,943.00 Pieces`, upper-case categories (`WALL MOUNT`), 31 rows
without a category, no Arabic names, no images, old SKUs like `0001 black1074`, and a junk footer row.

## Decisions
- **PS1 — SKU format.** `HMD00` + the number, at least 3 digits: `HMD00001`, `HMD00002`, … `HMD00999`,
  `HMD001000`. Drawn from a `SKU` counter inside the save transaction (like entry numbers), so SKUs are
  unique and in order. Not editable. The migration renumbers existing products in the order they were
  created and sets the counter.
- **PS2 — Names.** Only one name is needed: the Arabic name is optional on the form and in the import and
  copies the English one when left empty. When a file has no model code column, the product name is
  used as the model code (the old software's "Product" is the model code, e.g. `Ham-114`, `0001 black`).
- **PS3 — One product per model code.** Rows of the file with the same model code are **merged**: stock
  is kept per warehouse, categories are combined, the first non-empty price / name / image is used and a
  different value in a later row is shown as a warning.
- **PS4 — Stock.** A stock column becomes an **opening-stock entry** per warehouse (the ledger rule:
  stock only changes through entries). Only for products **created** by the import; for existing products
  the stock column is ignored (shown as a warning — use stock in or a correction). The warehouse column's
  values are matched to warehouses by name; the user can change each one, or let the import **create** a
  warehouse with that name. A cell listing several warehouses uses the first, with a warning.
- **PS5 — Categories.** Matched to existing ones ignoring case, a leading "TV", and plurals
  (`WALL MOUNT` = "TV wall mounts", `FLOOR STAND` = "Floor stands"); new ones are created with the name in
  title case. Rows without a category get the category the user picks (default: a new "Other").
- **PS6 — Clean-up.** Currency signs/words and units are stripped from prices and stock; a row whose filled
  cells all hold the same text (the old software's footer) is ignored; an images cell with several links
  uses the first. A SKU column only finds existing products (re-importing this app's export); other
  values (the old software's SKUs) are ignored.
