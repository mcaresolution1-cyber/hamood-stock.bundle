# Hamood Stock v1

## Summary
Ships the first usable version: ADMIN manages products (incl. Excel/CSV import), warehouses, users and
opening stock; ADMIN and STAFF record Stock In / Stock Out / Transfers through one ledger service
(`src/server/stock/`), ADMIN can void and correct; everyone (ADMIN / STAFF / VIEWER) sees the entry list,
printable delivery notes, a dashboard, product stock cards and four Excel-exportable reports. Cost and
stock value are ADMIN-only end to end. Mobile-first, EN + AR (RTL).

**Entry-service placement (spec ordering constraint):** Phase 1's opening-stock import must save through the
entry service, but the spec lists the service in Phase 2. The plan therefore builds the **service core**
(`createEntry` with counter, line merge, IN upsert and OUT conditional update, plus numbering + IN tests) as
the second-to-last block of Phase 1, immediately before the opening-stock task. Phase 2 *extends* the same
file (transfers, void, remaining tests) and builds the forms on top. Phase order 1→4 is unchanged.

## Non-goals
- Barcodes / scanning (spec excludes).
- WooCommerce sync — `wooProductId` stays unused; the website order no. is free text in `reference`.
- Back-dated entries: `entryDate` = now; no date picker in v1.
- Editing or deleting entries (immutable; void + re-enter).
- Hard delete of anything; "set quantity" screens; StockLevel rebuild UI (a read-only ledger check
  exists for tests only).
- Self-service password change / forgot-password emails (ADMIN resets passwords).
- External file storage (S3 / Vercel Blob): delivery-note photos are stored in Postgres (see Data model).
- Multi-currency, purchase orders, supplier master data (supplier name is free text).

## Data model changes
| Change | Migration | Constraint / backfill |
|--------|-----------|-----------------------|
| Phase 1: none (opening stock uses existing `IN` + `OPENING_STOCK`) | — | — |
| Phase 2: `StockEntry.customerPhone String?` (Direct sale) | `20261010000000_entry_extras` | nullable, no backfill |
| Phase 2: new `Attachment` model `{ id, data Bytes, mimeType, size Int, createdById → User, createdAt timestamptz }` (delivery-note photo; `StockEntry.photoUrl` stores `/api/attachments/<id>`) | same | `CHECK (size > 0 AND size <= 5242880)`, `CHECK (mimeType IN ('image/jpeg','image/png','image/webp'))`; `tests/helpers/db.ts` already truncates `"Attachment"` |
| Phase 2: one void per entry | same | `CREATE UNIQUE INDEX "StockEntry_one_void_per_entry" ON "StockEntry"("linkedEntryId") WHERE type = 'VOID'` |
| Phase 2: VOID type ⇔ VOID reason | same | `CHECK ((type = 'VOID') = (reason = 'VOID'))` |
| Phase 2: transfer pair link (decision T2) | none | one-way: `TRANSFER_IN.linkedEntryId` → `TRANSFER_OUT`; partner of an OUT found via `linkedFrom` filtered by `type = TRANSFER_IN`. No FK change, no update of saved entries |
| Phase 3: none (uses existing indexes on `StockEntryLine.productId`, `StockEntry.entryDate`) | — | — |

Void reason: stored in the VOID entry's `note` (required by Zod) — no new column. Migration SQL rules:
CHECKs appended at the end, no semicolons in comments, schema + migration committed together
(`pnpm db:migrate:wasm create entry_extras` if the native engine is blocked).

## Shared building blocks (used across phases)
| File | Purpose |
|------|---------|
| `src/lib/stock/policy.ts` (+ `.test.ts`) | Pure matrix: `allowedReasons(role, direction)`, `assertEntryAllowed(user, input)` — reason↔type mapping, ADMIN-only reasons (Correction ±, Return to supplier, Damaged/lost), warehouse checks: STAFF must be assigned to the transfer **source**; destination may be any active warehouse (decision Q1) |
| `src/lib/stock/lines.ts` (+ `.test.ts`) | `mergeLines()` (sum duplicate products, sort by `productId` for lock ordering), `signedQuantity(type, voidedType?)` |
| `src/server/stock/createEntry.ts` | The single write path; takes a `PrismaClient` (prod passes `db`, tests pass `testDb`) and runs `client.$transaction(tx => createEntryInTx(tx, …))`; `createEntryInTx` is exported for composition (void, transfer) |
| `src/server/stock/errors.ts` | `InsufficientStockError { productId, modelCode, warehouseName, available }`, `EntryRuleError(key)` |
| `src/server/queries/*.ts` | `server-only` read functions; take `user` and build `select` with `cost` only when `can(role,"cost:view")` |
| `src/lib/validation/*.ts` | Zod schemas shared by forms and actions; messages are translation keys |
| `src/server/auth/dal.ts` | add `requirePagePermission(action)` → redirects to `/` with a `forbidden` toast param instead of throwing (pages) |

Counter (decision T1): plain `UPDATE "Counter" SET value = value + 1 WHERE key = $k RETURNING value` as CLAUDE.md prescribes; key typed as `CounterKey`; 0 rows → throw (seed creates all counters; `resetDatabase()` re-inserts them)
inside the transaction (atomic like the `UPDATE … RETURNING` in CLAUDE.md, but safe when a counter row is
missing — tests truncate `Counter`). Flagged in Conflicts below.

## Risks
| Risk | Mitigation |
|------|------------|
| Opening stock needs the entry service a phase early | Service core built in Phase 1 (before opening-stock task) with its own tests; Phase 2 only extends it — no second write path is ever created |
| Overselling under concurrency | SQL conditional `UPDATE … quantity >= x`; no JS read-then-write; CHECK `>= 0` backstop; concurrency test |
| Deadlocks between multi-line entries | `mergeLines` sorts by `productId`; transfer always locks source before destination; void locks the original row first |
| Insufficient-stock message needs the available qty after the failed update | Read available qty in a fresh query **after** the transaction rolled back; message is informational, the server check is authoritative |
| Counter gaps | Counter is bumped inside the tx, so a rolled-back save doesn't consume a number; tested |
| VOID direction is not encoded by `type` | `signedQuantity(type, voidedType)` used everywhere (stock card, ledger check, reports); unit-tested |
| Cost leak to STAFF (UI, actions, picker, exports, RSC props) | Cost only in `select` when `can(role,"cost:view")`; tests assert key absence; auditor checks every new query |
| Decimal money maths | `Prisma.Decimal` / SQL arithmetic only, never `Number(cost)` |
| Photo storage in Postgres grows DB | Client-side resize, 4 MB CHECK, image MIME CHECK; can move to blob storage later (photoUrl is an opaque URL) |
| Server action body size for imports/photos | `experimental.serverActions.bodySizeLimit: "4mb"`; reader rejects > 2 000 rows |
| Import updates overwrite data with blanks | Rule in Decisions log; preview shows field-level changes before apply |
| Spreadsheet formula / CSV injection in exports | Write values as typed cells; prefix strings starting with `= + - @` with `'` |
| Slow reports as ledger grows | Indexed filters, pagination, aggregate in SQL, exports capped at 50 000 rows with a message |
| RTL / mobile regressions | Logical classes, `/screens` at 375px EN+AR every UI phase, Phase 4 sweep |
| Time zone boundaries ("today", months) | All bucketing in SQL with `AT TIME ZONE 'Asia/Riyadh'`; boundary test |

## Edge cases the plan must cover
- [ ] Opening stock with > 50 products saves as one entry (line limit must not apply); detail/print usable with hundreds of lines
- [ ] Second opening-stock upload for a warehouse shows a warning and needs explicit confirmation (Q6)
- [ ] Inactive product usable for out/transfer/correction but not Stock In/import (Q7); voids of old entries for inactive products/warehouses still work
- [ ] Changing a warehouse's kind while it holds stock is rejected
- [ ] Transfer: both halves saved; IN links to OUT; partner lookups filter by type (VOID entries also link); STAFF assigned only to the source can transfer (Q1)
- [ ] Concurrent voids of both halves of one transfer: exactly one succeeds, no deadlock, friendly "already voided"
- [ ] Void of a transfer whose destination stock already left: rejected, nothing changes
- [ ] Void of a VOID rejected; double void rejected by service and unique index
- [ ] Damaged return with 0 or 2+ Damaged warehouses: form asks/blocks; STAFF not assigned to Damaged can still record it (Q2), but not any other reason into Damaged
- [ ] Sales reasons from a Damaged warehouse rejected on the server (Q4)
- [ ] Empty Counter table → first number IN-000001; failed save doesn't advance the counter
- [ ] `photoUrl` only accepts `/api/attachments/<id>`; > 4 MB or non-image rejected; orphans tolerated and private
- [ ] `/api/attachments/[id]` for signed-out or deactivated user → 401/redirect
- [ ] Low stock: no StockLevel row = 0; minimum 0 per Q5; Damaged and inactive excluded; dashboard count = report rows
- [ ] Import: model code trimmed + case-insensitive; numeric cell `772` stays "772"; empty cell keeps value (Q8); unknown category lists allowed ones; `1,250.50` and Arabic-Indic digits handled deliberately (never float); BOM header; > 2,000 rows or > 2 MB rejected
- [ ] No `cost`/`value` key in any STAFF/VIEWER server response, export or RSC props
- [ ] Phone: Saudi formats and Arabic-Indic digits normalised, shown `dir="ltr"`; visibility per Q11
- [ ] "Today's entries" uses the Riyadh day; transfer counts once; VOID entries excluded
- [ ] Out-by-reason: 23:30 Riyadh on the last day of a month falls in that month; voided entries and voids excluded
- [ ] Self/last-admin deactivate or demote rejected; deactivated mid-session user rejected on next action/export
- [ ] STAFF with zero warehouses sees empty states; un-assigned mid-form → rejected on save
